Count drawing entities by type

Count selected lines, circles and block references without changing the drawing.

During a drawing review, a quick breakdown of selected entities can help you understand its contents. GCTCOUNT groups main entities by their internal type and prints a command-line report. It is an initial review tool, not a construction quantity takeoff.

How to use

  1. Save the code as GCTCOUNT.lsp or use Download.
  2. Load the file with APPLOAD in an AutoCAD edition that supports AutoLISP. Keep normal security settings and use a trusted file location.
  3. Run GCTCOUNT, select objects and press Enter.
  4. Read the report in command-line history.

Complete source code

Download code
(defun c:GCTCOUNT (/ ss idx data kind counts old row)
  (prompt "\nSelect objects to count by entity type: ")
  (setq ss (ssget))
  (if ss
    (progn
      (setq idx 0 counts nil)
      (repeat (sslength ss)
        (setq data (entget (ssname ss (float idx)))
              kind (cdr (assoc 0 data)))
        (if kind
          (progn
            (setq old (assoc kind counts))
            (if old
              (setq counts (subst (cons kind (1+ (cdr old))) old counts))
              (setq counts (cons (cons kind 1) counts)))))
        (setq idx (1+ idx)))
      (princ "\n--- GeoCAD Tools: Entity Count ---")
      (foreach row (reverse counts)
        (princ (strcat "\n" (car row) ": " (itoa (cdr row)))))
      (princ (strcat "\nTotal selected: " (itoa (sslength ss)))))
    (prompt "\nNo objects selected."))
  (princ))
(princ)

Illustrative example

Expected example: three lines, two circles and one block reference produce LINE: 3, CIRCLE: 2 and INSERT: 1, for a total of 6.

Limitations and verification

Each block reference counts once; nested contents are excluded. INSERT may include external references. Associative arrays do not necessarily count their visible items separately. Internal names such as LWPOLYLINE are displayed. Not run in AutoCAD: verify on a simple drawing with known counts first.

Reference specification or documentation

Open-source example: always test with a copy before real-world use.
